## Overview

Raley Emails Notifications lets you send fully customized emails and Slack messages straight from your Jira or Jira Service Management (JSM) projects — without leaving the tool your team already uses.

## How It Works

The app runs as an Atlassian Connect cloud add-on. When a configured trigger fires (a workflow transition, a schedule, or a manual send), the app reads the relevant Jira issue data and sends the email through your configured sending method.

```text
Jira workflow transition / schedule / manual trigger
       ↓
Raley Emails Notifications app (Atlassian Connect)
       ↓  reads issue data via Jira REST API
Raley AppServer assembles the email from your template
       ↓
Sends via: Raley shared mail server  OR  your SMTP server  OR  Gmail OAuth
       ↓
Recipient's inbox
```

**Sending options:**

| Method | Best for |
| --- | --- |
| Raley shared mail server | Quick setup, no SMTP credentials needed |
| Your own SMTP server | Custom sender domain, compliance requirements |
| Gmail OAuth | Gmail accounts — enables email threading via Message-ID |

The app reads Jira issue data (fields, comments, user info) but does **not** persistently store issue content. Configuration (templates, triggers) is backed up for 30\+ days. See [Data Security and Privacy](/policies/data-security-and-privacy).

## What You Can Do

- Send **email attachments** directly from customer requests
- Distribute **Issue PDF snapshots** in notifications
- Notify users automatically on **workflow transitions**
- Set up **scheduled digest notifications**
- Include full **comment history** in outgoing emails
